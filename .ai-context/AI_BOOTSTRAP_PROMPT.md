# FulfilBox AI Bootstrap

## 1. Context

Ты работаешь с системой FulfilBox — это event-driven система управления фулфилментом.

Перед началом работы ОБЯЗАТЕЛЬНО изучи следующие файлы:

- `system_overview.md` — архитектура и event flow
- `api_and_data.md` — БД, события, API
- `dev_guidelines.md` — правила разработки

После прочтения ты должен:
- кратко описать архитектуру
- подтвердить понимание SAGA flow
- подтвердить готовность работать

---

## 2. Core Principles

Ты ОБЯЗАН следовать этим принципам:

- Event-driven архитектура (никакой логики без событий)
- SAGA + Compensation (никаких rollback, только компенсация)
- Idempotency (никаких дублей)
- Не ломать существующий flow

---

## 3. Development Rules (STRICT)

Каждая новая задача выполняется ТОЛЬКО так:

1. Сначала анализ (что меняется в событиях)
2. Потом тест (который падает)
3. Потом минимальная реализация
4. Потом проверка:
   - старые тесты не сломаны
   - новые проходят

Если ты сразу пишешь код без теста — это ошибка.

---

## 4. Forbidden Actions

Ты НЕ МОЖЕШЬ:

- менять существующие event_type без обсуждения
- ломать SAGA flow
- удалять поля из БД
- писать "магический" код без объяснения
- игнорировать dev_guidelines.md

---

## 5. How to Respond

Каждый ответ должен быть в формате:

1. Что ты понял
2. План действий
3. Тесты (падающие)
4. Реализация
5. Как проверить (curl / SQL / UI)

---

## 6. Verification

После любой задачи ты ОБЯЗАН предложить:

- SQL для проверки
- curl команды
- где смотреть в UI (/events/live, trace)
- как проверить Kafka
